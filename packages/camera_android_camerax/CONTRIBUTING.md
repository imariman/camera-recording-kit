# Contributing to camera\_android\_camerax

## Plugin structure

The `camera_platform_interface` implementation is located at
`lib/src/android_camera_camerax.dart`, and it is implemented using Dart classes
that are wrapped versions of native Android Java classes.

In this approach, each native Android class used by the plugin is represented
by an equivalent Dart proxy class. Instances of these classes are paired and
represent each other in Dart and on the JVM. The proxy classes and the
communication layer between them are generated by [`pigeon`][1] from the
`@ProxyApi` definitions in `pigeons/camerax_library.dart`:

* `lib/src/camerax_library.g.dart` contains the generated Dart proxy classes,
  their `PigeonInternalProxyApiBaseClass` base class and the Dart
  `PigeonInstanceManager`.
* `android/src/main/java/io/flutter/plugins/camerax/CameraXLibrary.g.kt`
  contains the generated Kotlin `PigeonApi<Name>` classes and the native
  `CameraXLibraryPigeonInstanceManager`.

The two instance managers map shared `int`/`long` identifiers to objects and
notify each other when an object becomes unreachable or is removed, so native
resources are released without manual bookkeeping. Generated Dart proxy classes
also have detached constructors, which create instances that are not attached
to the instance manager or a native object, to simplify testing.

`lib/src/camerax_library.dart` re-exports the generated classes and adds the
hand-written pieces that Pigeon cannot generate, such as the generic `LiveData`
and `Observer` wrappers. In `android/src/main/java/io/flutter/plugins/camerax/`,
each wrapped class has a `<Name>ProxyApi.java` implementation of the generated
`PigeonApi<Name>` class, registered in `ProxyApiRegistrar.java`. These
implementations should directly delegate calls to CameraX or the other wrapped
Android libraries and should not add logic or abstraction; any exceptions
should be thoroughly documented in the code.

If a CameraX or other Android class that you need is not wrapped yet, add a
`@ProxyApi` definition for it to `pigeons/camerax_library.dart`, regenerate
with `dart run pigeon --input pigeons/camerax_library.dart`, implement its
`<Name>ProxyApi.java` and register it in `ProxyApiRegistrar.java`. Regenerate
mocks with `dart run build_runner build -d` when tests mock the new class.
Never edit the generated `*.g.dart` or `*.g.kt` files by hand.

For more information, please see the [design document][2] or feel free
to ask any questions on the #hackers-ecosystem channel on [Discord][4]. For
more information on contributing packages in general, check out our
[contribution guide][3].

## Testing

While none of the generated `pigeon` files are tested, all plugin impelementation and
wrapped native Android classes (Java & Dart) are tested. You can find the Java tests under
`android/src/test/java/io/flutter/plugins/camerax/` and the Dart tests under `test/`.

Run the Dart tests with `flutter test` from this directory. The Java tests need a
Flutter host app because this package ships no example app or Gradle wrapper and
its `build.gradle.kts` reads `flutter.compileSdkVersion`; run them with
`tool/test_android_jvm.sh` from the repository root (JDK 17 or newer). Every Java
test runs against Robolectric SDK 35, pinned in
`android/src/test/resources/robolectric.properties`, so the suite works on JDK 17
(Robolectric SDK 36 requires JDK 21). Keep new Robolectric tests on that pin unless
they need a newer SDK, in which case document the JDK requirement.

For the upstream approach to running plugin tests, see the [running plugin tests guide][5].
